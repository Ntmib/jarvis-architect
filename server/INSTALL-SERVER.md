# Безопасная установка Агента на VPS

> Этот файл читает Claude Code. Пользователь — новичок. Объясняй каждый шаг
> простыми словами и не проси присылать пароли, токены, приватные ключи или
> коды авторизации в чат.

## Главные правила безопасности

1. Не спрашивай пароль root и токен Telegram-бота в переписке.
2. Не подставляй секреты в команды, `expect`, аргументы процессов и файлы
   проекта.
3. Не отключай проверку подлинности SSH-сервера.
4. Не выполняй `git push` автоматически.
5. Первичная настройка выполняется пользователем в защищённой консоли
   хостинга. Секреты вводятся только в скрытые терминальные поля.
6. Если пользователь уже прислал секрет в чат, не повторяй его и предложи
   заменить после настройки.

## Что должно быть у пользователя

- новый VPS на Ubuntu 22 или 24;
- доступ к панели хостинга и встроенной консоли VPS;
- VS Code на компьютере;
- локальная папка Агента с DNA-файлами.

## Шаг 1. Проверь локальные файлы

В текущей папке проверь наличие основных файлов:

```bash
ls CLAUDE.md SOUL.md MEMORY.md GOALS.md 2>/dev/null
```

Если их нет, не ищи по всему компьютеру автоматически. Попроси пользователя
открыть Claude Code именно в папке Агента.

## Шаг 2. Установи окружение через консоль хостинга

Не подключайся к серверу по паролю из Claude Code.

Попроси пользователя:

1. Открыть сайт хостинга.
2. Перейти в раздел VPS.
3. Открыть встроенную консоль нужного сервера.
4. Войти как `root`. Пароль вводится в консоли и не отправляется в чат.
5. Выполнить:

```bash
wget -O /root/setup-agent.sh https://raw.githubusercontent.com/Ntmib/jarvis-architect/main/setup-server.sh
bash /root/setup-agent.sh
rm /root/setup-agent.sh
```

Попроси написать только `готово` или прислать скриншот ошибки без паролей и
токенов.

Скрипт устанавливает Node.js, Claude Code CLI, пользователя `agent`, рабочие
папки и безопасные настройки разрешений.

## Шаг 3. Настрой VS Code Tunnel

В консоли VPS пользователь получает имя подготовленного туннеля и запускает
авторизацию от непривилегированного пользователя `agent`:

```bash
TUNNEL_NAME=$(systemctl cat agent-tunnel.service | sed -n 's/.*--name //p' | tail -1)
sudo -u agent -H code tunnel --accept-server-license-terms --name "$TUNNEL_NAME"
```

На экране появятся ссылка GitHub и одноразовый код. Код вводится только на
странице GitHub и не отправляется в чат.

После авторизации пользователь нажимает `Ctrl+C`, затем запускает уже
подготовленный systemd-сервис:

```bash
systemctl enable --now agent-tunnel.service
```

Сервис настроен с `User=agent`, поэтому удалённый VS Code не получает root-
права. Если сервис уже включён, это не ошибка.

## Шаг 4. Подключись к серверу из VS Code

Объясни пользователю:

1. Открыть VS Code.
2. Открыть Remote Explorer.
3. Выбрать раздел Tunnels.
4. Выбрать свой сервер.
5. Открыть папку `/home/agent/workspace/`.

В этом процессе не нужны SSH-пароли, `expect`, `scp` и отключение проверки
ключа сервера.

## Шаг 5. Перенеси файлы Агента

Через проводник VS Code пользователь перетаскивает в
`/home/agent/workspace/` свои файлы:

- `CLAUDE.md`;
- `SOUL.md`;
- `MEMORY.md`;
- `GOALS.md`;
- `USER.md`;
- `MISSION.md`;
- `PROJECTS.md`;
- `PREFERENCES.md`;
- `LEARNED.md`;
- папки `memory/` и `knowledge/`, если они нужны.

Перед переносом напомни:

- в `memory/` не должно быть чужих дневников;
- `.env`, пароли, токены, cookies и приватные ключи переносить нельзя;
- персональные файлы нельзя публиковать в открытом GitHub.

Если права файлов нужно исправить, пользователь выполняет от root в консоли
хостинга:

```bash
chown -R agent:agent /home/agent/workspace
```

## Шаг 6. Авторизуй Claude Code

В терминале VS Code на сервере пользователь выполняет:

```bash
sudo -u agent claude auth login
```

Ссылка открывается в браузере. Код авторизации вставляется обратно только в
терминал Claude Code. Не проси отправлять код в чат.

Проверка:

```bash
sudo -u agent claude --version
```

## Шаг 7. Проверь файлы и память

В терминале VS Code выполни:

```bash
find /home/agent/workspace -maxdepth 2 -type f | sort
```

Проверь:

- присутствуют DNA-файлы;
- в `memory/` нет дневников другого человека;
- нет `.env`, ключей и токенов;
- владельцем файлов является `agent`.

Не выводи содержимое персональных файлов без необходимости.

## Шаг 8. Telegram-бот — только через скрытый ввод токена

Если пользователь хочет Telegram-бота, не спрашивай токен в чате.

Попроси открыть консоль VPS от root и выполнить:

```bash
wget -O /root/setup-agent-bot.sh https://raw.githubusercontent.com/Ntmib/jarvis-architect/main/setup-bot.sh
bash /root/setup-agent-bot.sh
rm /root/setup-agent-bot.sh
```

Скрипт попросит токен в терминале со скрытым вводом, проверит формат, запишет
его в защищённый `.env` и запустит сервис. В истории команд токен не
сохраняется.

После установки скрипт покажет одноразовый код привязки. Пользователь отправляет
боту `/start КОД`. Без правильного кода бот никого не назначит владельцем.
Код и username нельзя публиковать до завершения привязки.

## Шаг 9. Git и резервная копия

Работа Агента не требует GitHub. По умолчанию личные файлы остаются только на
компьютере и сервере.

Если пользователь хочет резервную копию:

1. использовать только приватный репозиторий;
2. проверить `git status --ignored`;
3. проверить список подготовленных файлов через `git diff --cached --name-only`;
4. не добавлять `.env`, DNA-файлы, `memory/` и `knowledge/`, пока пользователь
   отдельно не решил хранить их в приватном репозитории;
5. выполнять push только после отдельного явного подтверждения.

Если видимость репозитория не проверена, push запрещён.

## Итоговая проверка

Установка завершена, когда подтверждено:

- окружение установлено;
- VS Code подключается к серверу;
- файлы находятся в `/home/agent/workspace/`;
- Claude Code авторизован;
- чужих дневников и секретов нет;
- Telegram-бот работает, если пользователь его устанавливал;
- личная память не опубликована в открытом GitHub.

В финальном сообщении дай только понятный результат и один следующий шаг. Не
показывай пароли, токены, коды авторизации и содержимое `.env`.
