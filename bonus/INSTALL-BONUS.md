# Безопасная установка бонусного пакета

> Инструкция для Claude Code. Не проси пользователя присылать одноразовый
> токен, пароль root, Telegram Bot Token или код авторизации в чат.

## Шаг 1. Скачать пакет через скрытый ввод токена

Попроси пользователя открыть обычный терминал и выполнить:

```bash
curl -fsSL https://raw.githubusercontent.com/Ntmib/jarvis-architect/main/bonus/download_bonus.py -o /tmp/download_bonus.py
python3 /tmp/download_bonus.py
rm /tmp/download_bonus.py
```

Скрипт сам запросит одноразовый токен в скрытом поле. Токен не попадёт в
командную строку, историю терминала или сообщения Claude Code.

Если токен недействителен или закончился лимит, пользователь получает новый
через `/new` у `@jarchitect_bot` и повторяет команду. Не проси копировать токен
в чат.

Пакет устанавливается в `~/jarvis-bonus`. Если папка уже не пустая, скрипт
останавливается и ничего не перезаписывает.

## Шаг 2. Проверить пакет

После сообщения пользователя `готово` проверь только структуру:

```bash
find ~/jarvis-bonus -maxdepth 2 -type f | sort | head -100
```

Не выводи содержимое файлов с лицензией, персональной памятью или секретами.

## Шаг 3. Выбрать сценарий

Спроси один раз:

1. Установить Агента локально в новой пустой папке.
2. Установить на VPS через безопасную консоль хостинга.
3. Добавить компоненты в существующего Агента без замены памяти.

### Локальная установка

Открой `~/jarvis-bonus/INSTALL.md` и следуй ему. Не используй `degit --force`
и не устанавливай поверх непустой папки.

### Установка на VPS

Открой `~/jarvis-bonus/server/INSTALL-SERVER.md`. Не спрашивай пароль root или
токен Telegram-бота в чате. Первичная установка выполняется пользователем во
встроенной консоли хостинга, токен бота вводится скрыто через `setup-bot.sh`.

### Перенос в существующий проект

1. Сначала покажи список файлов, которые собираешься добавить.
2. Не перезаписывай `CLAUDE.md`, `SOUL.md`, `MEMORY.md`, `GOALS.md`, `USER.md`,
   `MISSION.md`, `PROJECTS.md`, `PREFERENCES.md`, `LEARNED.md`, `memory/` и
   `knowledge/` без отдельного подтверждения.
3. Копируй только выбранные пользователем скиллы, код бота или серверные
   инструкции.
4. Не выполняй push автоматически.

## Безопасность GitHub

Личная память по умолчанию остаётся локально. Если пользователь хочет
резервную копию, допустим только приватный репозиторий после проверки
`git status --ignored` и `git diff --cached --name-only`.

Не публикуй персональные файлы в открытом репозитории и не отправляй их наружу
без явного подтверждения.
